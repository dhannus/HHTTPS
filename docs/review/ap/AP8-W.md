### [S3] [Wartbarkeit] server/public/index.html:L384-1058 — Die Sign-in-Seite ist ein 675-zeiliges Inline-Skript-Monolith, das nur per Regex getestet werden kann
**Begründung:** Der gesamte Sign-in-Client (i18n-Wörterbuch L398-485, Session/E-Mail/Passkey/EUDI/Alter/GitHub/Maschine L546-778, Identity-Publikation L786-843, ESCO/iamhmn-Karte L851-934, Restore/Magic-Link/login_hint L941-1052) liegt in einem einzigen `<script>`-Block ohne Modulgrenzen. Ein umformatierter Funktionsabschluss (`\n}`) oder ein Leerzeichen im Body-Literal lässt die Tests fehlschlagen, ohne dass sich Verhalten ändert.
**Auswirkung:** Jede Änderung an der Seite ist ein Blind-Edit in einer 1.060-Zeilen-Datei; Tests sind formatierungs- statt verhaltensabhängig und geben falsche Sicherheit bzw. falsche Alarme.
**Empfehlung:** Skript in `public/js/signin/{i18n,session,email,passkey,eudi,machine,identity}.js` als ES-Module auslagern (die Seite lädt bereits `iamhmn-card-issuer.js`-fähige Modul-Infrastruktur nicht — siehe nächstes Finding); Unit-Tests dann gegen importierte Funktionen statt Regex schreiben, Playwright-E2E bleibt für das DOM.

- S1: 0

Gesamteindruck: Das Frontend besteht aus drei parallel gepflegten Inline-Monolithen (index.html, sites/hhttps.html, wallet.html), die denselben Sign-in-Flow, dieselbe Identity-Publikation und drei divergierende Rollen-Kataloge jeweils eigenständig implementieren; die Tests spiegeln diesen Zustand, indem sie Funktionsrümpfe per Regex aus HTML schneiden. Im Ordner `server/public` liegen mehrere tote oder nicht angebundene Artefakte (workload.html mit nicht existierenden Endpunkten, email-verify.html, email-patch.js, iamhmn-card-issuer.js), und die öffentlich sichtbare Doku (spec.html, INSTALL.md, EMAIL_SETUP.md, FINALIZE-NOTE.md) beschreibt Versionen, Pfade und Datenflüsse, die der Code nicht mehr hat. Die Extension ist funktional kompakt, trägt aber ungetesteten, teils wirkungslosen Code (Header-Sniffer, Sign-Mode-Einstellung, tote Message-Handler) und Versions-/i18n-Drift. Eine gemeinsame Client-Bibliothek für Session/E-Mail/Passkey/Identity plus das Löschen der toten Seiten würde den Großteil der Befunde schließen.
